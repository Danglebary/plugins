# 0006 — Coverage claims split by attestability

## Context

pirr's analytical surface — thirteen shipped reviewer agents, dispatched by `/refactor` through a per-repo Reviewers manifest (this repo's lists seven of them), plus the close-out pair (`deviation-fact-checker`, `spec-conformance`) invoked by `/done` and `/retro` — makes claims about a diff. Nothing in the corpus states what counts as having *checked* something, and the one place the question was addressed, it was addressed twice, incompatibly. `/refactor`'s reviewer brief requires *"for each area of your lens you examined and found clean, say 'checked, clean' — silence is indistinguishable from not-looked,"* while every reviewer agent body ends *"If no candidates surface, output `_No <lens> candidates._` and stop."* Two contradicting instructions arrive in one executor's context, and thirteen agents have been resolving the contradiction in the agents' favor.

This is not a hypothetical. `docs/reviews/2026-07-08-whole-plugin-deep-dive.md` recorded it as a confirmed Tier-2 finding — *"nine subagents receive contradictory instructions and the merge layer can't distinguish clean from not-looked, the exact gap the requirement exists to close"* — with the fix direction *"pick one side of the checked-clean contract and change all nine agents plus the brief together."* Neither side was picked; the reviewer set has since grown from nine to thirteen. Separately, spec 002's retro records the failure mode this gap conceals: a newly authored agent *"isn't a registered dispatch type until the plugin reloads, so the first live `/done` ran the new spec-conformance agent inlined into a generic agent"* — a lens that did not run, producing output indistinguishable from one that did.

The corpus states the governing principle correctly in exactly one place and for exactly one claim. `IMPLEMENTATION-LOOP.md` pins verification green as *"a **positive** signal, never an assumed one."* Every other claim-making surface asserts against a diff with no stated evidence contract and no vocabulary for a partial result.

## Decision

A coverage claim is made by the layer that can attest to it, and by no other.

The **dispatch layer** — `/refactor` and `/done` — carries a **resolution preflight** and an **anti-substitution rule**, and keeps a **dispatch record**. The preflight is the load-bearing half: before dispatching, every named `subagent_type` is checked against the available agent types, and an unresolved name refuses, naming it. The anti-substitution rule states the corollary the recorded incident actually needed — a `subagent_type` that does not resolve means *that lens did not run*; it is never recovered by inlining the agent's body into a general-purpose agent. The dispatch record then states which lenses were dispatched, which returned, and which refused or failed to resolve.

The **agent layer** carries a partial-verdict register whose **contents are gap-only** but whose **emission is mandatory**. It lists only surfaces within a lens the agent actually ran that went unavailable, denied, or unconsulted, naming the surface and what it would have confirmed — it never enumerates what *was* checked. When there is no gap it emits the sentinel `_Full._`, and the register is placed so that no halt instruction precedes it.

The sentinel is what makes the register enforceable rather than merely stated. Silence is not an available outcome: a return carrying no register is **off-contract**, which is the only post-hoc signal the dispatch layer has. `_Full._` is not itself a coverage claim — it records that the gap check ran. Its cost is one token, so the objection that defeated the enumerated form does not reach it.

The **empty-read corollary** binds where an empty search is used as evidence of absence, and only there. A search returning nothing supports a *missing* or *dropped* finding only when the agent can name what it searched — pattern and paths — **and** the same search matched something known to be present. Without that positive control the empty result is an unresolved surface: it goes in the register, not in a findings section. It is scoped to negative findings deliberately; an empty read can never be evidence *for* presence, so unscoped it would cost *O(searches)* and reproduce the cost shape that defeated the enumerated form.

The rule, the register, the empty-read corollary, and the dispatch record live in one principle doc cited by the agents and both dispatching skills. The verification-tier vocabulary carried by the `work-pirr` fork's equivalent contract is not adopted.

## Consequences

- The fifteen plugin-shipped agents gain a partial-verdict register in their output contracts; `AGENT-FORMAT.md` places it inside the documented output-contract shape so future agent authors inherit it.
- The close-out pair is **not** exempted, despite being the only parse-coupled agents — they carry the corpus's sharpest empty-read hazard, converting an empty grep into a positive "missing requirement" finding. Their contract is restated as **three *finding* sections followed by the register**, with the register outside the parse contract; the count language was always over-specified, since the calling skill is prose reading headings, not a parser. A precedence line keeps the two from colliding: findings keep their own "couldn't verify" caveats, while the register records **surfaces**, never findings.
- The cost of not exempting them is sync-set breadth: "three sections" is a documented must-stay-in-sync phrase across both agent bodies, `/done`, `/retro`, `AGENT-FORMAT.md`, `CONTEXT.md`, and the READMEs. Every one moves in the same sweep.
- `/refactor`'s brief loses its per-area "checked, clean" requirement — the contradiction is resolved by deleting the enumerated form, not by propagating it.
- `/refactor` and `/done` gain a resolution preflight, an anti-substitution rule, and a dispatch record. This pulls **Lifecycle layer** skills into a change otherwise scoped to the **Knowledge layer**, so the work does not back-port cleanly to the `work-pirr` fork, which ships its own lifecycle skills.
- The dispatch record is **persisted, not merely presented** — it rides the per-ticket retro entry `/done` already appends, with `/refactor` appending its own line to the same entry. `RETRO-FORMAT.md` gains the field. Emission is mandatory and detail is gap-only, mirroring the register's `_Full._`: if nothing is written in the clean case, absence carries no meaning and the record is worthless. The rationale is `/refactor`'s own — *"a deferral that lives only in chat evaporates at the session boundary."*
- Accepted cost of persisting it: the record is an attestation nobody can audit, and writing it into a durable learning artifact lends it more authority than its evidentiary weight supports. The mitigation is wording — the record states what was dispatched and what returned, never that a lens was *correct*.
- The common case costs one token: a reviewer that ran its lens cleanly emits `_Full._`. Prose cost is billed only where a gap actually exists.
- The register must be **reachable**, which is a placement constraint, not a wording one. Every reviewer's output contract currently ends `output `_No <lens> candidates._` and stop` — a literal halt. A register appended after it is unreachable in exactly the case it exists for, since an unread surface and an empty candidate list correlate. The sweep restructures that line rather than appending to it.
- `/refactor`'s brief requires reviewers to verify external-system claims against the installed toolchain, but every reviewer's tool grant is `Read, Grep, Glob` — no execution tool. That instruction is unsatisfiable as written, so it is a guaranteed recurring register entry until the brief or the grant changes. It is the register's worked example.
- The degradation path was **fired against the live Agent tool on 2026-07-19**, and the result reshaped this decision. An unknown `subagent_type` **hard-errors** at the tool boundary and enumerates every registered type — it never silently falls back. A successful dispatch's return envelope carries **no agent identity**, and the subagent has no `subagent_type` in its own context and cannot self-identify. Output-contract shape is therefore **not** a degradation signal: the recorded failure inlined the agent's body, which carries its own output contract, so the degraded return was on-contract. Detection is available **only before dispatch**, never reconstructible after it.
- Consequently the dispatch record is an **attestation, not a verification** — nothing downstream can audit it, and the skill writing it is the same executor whose improvisation is the failure mode. It is homed in the principle doc as an honesty obligation of the same shape as the register, and the deterministic weight sits on the resolution preflight and the anti-substitution rule instead.
- The recorded spec-002 degradation was never a silent tool fallback. The dispatch hard-errored **visibly**, and the model recovered by inlining. What was missing was not detection but an instruction forbidding the recovery — which is why the anti-substitution rule, not the record, is the fix for that incident.
- A separate zero-signal path exists and is covered by the same rule: `subagent_type` is **optional** in the Agent tool's schema, and omitting it silently runs a general-purpose agent with no error and no marker. A skill that names agents in prose without pinning the exact type per call degrades invisibly.
- `/refactor` already carries a resolution preflight over the Reviewers manifest; `/done` has none, and `/done` is where the recorded incident happened. Porting it is the cheapest deterministic move available and closes the incident directly.
- What remains unverified: whether a `SubagentStop` or `PreToolUse(Task)` hook receives the agent type. No documented hook field carries it and no hook was fired. If one does, a genuinely mechanized dispatch record becomes possible and this ADR is amended rather than superseded.
- Rejecting the tier vocabulary means a future pirr operation that genuinely cannot be fired locally has no place to record that it was confirmed only against documentation. Should one appear, this ADR is superseded rather than amended.

## Alternatives considered

- **Enumerate coverage in the agents (the brief's existing form).** Rejected. It prices honesty at *O(areas examined)* per reviewer, layered on top of an output contract that already instructs *"don't pad"*. Cost is only half the diagnosis: the requirement lived in one sub-bullet of `/refactor`'s brief while its competitor was stated **twice inside the agent's own system prompt** — the terminal stop line and `Don't pad` — so it lost on position and authority as well as tokens. Restating it louder would not change the cost shape that defeated it. It also buys a self-report: an agent asserting it examined an area is the weakest available evidence that it did, and it is precisely the evidence a degraded dispatch would fabricate most confidently.
- **Drop the requirement entirely; the agent contract wins.** Rejected. It restores coherence at the price of the goal — silence stays indistinguishable from not-looked, and the spec-002 degradation recurs undetected.
- **The gap-only register alone, with no dispatch layer.** Rejected as the sole mechanism. Absent anything beside it, the absence of a register reads as "fully checked" — an assumed positive, which is the exact failure `IMPLEMENTATION-LOOP.md` forbids. This rejection originally rested on the dispatch record being a third-party observation; firing the tool refuted that (see Consequences), so it now rests on the **resolution preflight**, which genuinely is external to the agent: an unresolved type refuses at the tool boundary regardless of what any executor claims. The register survives its own objection because a lens that could not have run cannot reach the register at all.
- **Blocking this decision on a mechanized dispatch record via hooks.** Rejected for now. It is the only avenue that would make the record auditable rather than attested, but no documented hook field carries the agent type, so adopting it means a live hook experiment gating a decision whose deterministic half — the preflight — is already available and already precedented in `/refactor`. Should the hook field prove to exist, the record is upgraded from attestation to verification by amendment.
- **Adopt the fork's verification tiers (documented-vs-fired, with a named completing residual).** Rejected. Those tiers exist because that plugin authors against a credential-less box, where the two confirmations genuinely differ. Every operation pirr touches is locally fireable, so the tier would import bookkeeping for a distinction this repo cannot have.
- **Home the rule in `AGENT-FORMAT.md`.** Rejected once the dispatch record joined: that is a **Format doc**, defining the shape of an artifact type, and the rule now binds skills as well as agents — the Glossary's own definition of a **Principle doc**.
