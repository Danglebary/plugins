# Close-out correctness for the Personal workflow

## Problem

The 2026-07-07 whole-plugin review confirmed that the files store's git story breaks at close time, and this repo dogfoods pirr on the files store — so the workflow wedges on its own first ticket. Specifically: the "a status flip rides along with the ticket's next real commit" convention has no carrier at ticket or PRD close, so `/done`'s own close-out steps produce uncommitted edits that make its merge step refuse (reproduced live by a review verifier); `/retro`'s in-place rewrite can permanently destroy the running retro while asserting it is preserved in history; no skill owns the PRD→default-branch merge; spikes and ideas banked by `/to-prd` have no commit path at all; diff semantics are ambiguous at every call site that computes one (base, two-dot vs merge-base, no preflight — an empty diff yields a vacuous fact-check recorded as clean); and the `stacked` branching strategy is dead config that cannot work as written.

## Goals

- A full ticket lifecycle on the files store completes without a git refusal: `/done` ends with the close-out store edits committed on the ticket branch and a gated merge into the parent branch.
- `/retro` never destroys uncommitted work: on the files store it refuses to rewrite a running retro that isn't committed, and PRD close ends with the synthesized retro, the Done flip, and the active-pointer removal committed, followed by a gated PRD→default-branch merge offer mirroring `/done`'s gate — re-offered, not refused, on a `Done`-but-unmerged PRD.
- The planning phase (`/next-prd` → `/grill-me` high-level → `/to-prd` → `/grill-me` detail → `/to-tickets`) is codified as one chain that ends with the PRD branch cut and all planning artifacts landed as its first commit.
- Spikes and ideas banked by `/to-prd` get a gated commit offer — banked thoughts survive a fresh clone.
- Every diff any skill consumes is materialized by one deterministic mechanism with preflight checks; wrong-branch, dirty-tree, and empty-diff conditions refuse loudly instead of producing vacuous downstream results.
- The `stacked` strategy is removed; close-out prose is single-path.
- A no-op `/refactor` pass still ends at the close-out merge offer — no stranded ticket branches.
- Outside-PRD deferrals surfaced by `/improve` survive as banked Ideas instead of evaporating and being re-proposed every pass.

## Non-goals

- The Work workflow plugin (Jira ticket source, no-PRD track, PR-based close-out, feature-branch epics with stacked ticket PRs) — banked as an idea per ADR 0001.
- Notion backend hardening (Tickets schema number/slug, the retro section heading and edit protocol, root-page sharing, the live tool-contract smoke test) — a separate PRD candidate.
- The review's remaining contract repairs outside the close-out cluster (abandonment ownership, idea-promotion mechanics, `/tdd` integration, `/grill-me` PRD-edit discipline).

## Approach

- **Gated planning commits at both close points** *(files store only — notion's store edits are property/body updates independent of git with nothing to commit; notion skips the commit gates and proceeds straight to the merge gates, which are git-identical in both stores)*. Convention codified: implementation is committed on the ticket branch *before* `/done` runs — the diff script's dirty-tree preflight enforces it by refusing at `/done` start; the refusal names the convention and prints the offending paths. `/done` ends with a gated commit of its close-out edits on the ticket branch — defined as *every store edit made during this close-out invocation* (materialized deviations, retro entry, Done flip, any ADR minted at the candidate gate), never a fixed list — then forks on the user's choice: merge now per convention — *explicitly declining the per-ticket refactor pass* — or defer the merge to `/refactor`'s close-out offer (the step-10 recommendation folds into this fork; it is the decision point). No post-merge `/improve` mode exists: invoked after a merge-now, the skill routes to its existing ad-hoc arm and names the recoverable range (`<merge-commit>^1...<merge-commit>`; the `--no-ff` merge commit is findable by branch name) so scope is handed over deliberately, with refactor commits landing on the PRD branch and `(refactor)` captures still appending to the `Done` ticket. Committing before the fork means `/improve` always starts from a clean tree — no preflight special case. `/improve`'s outside-PRD deferrals also gain a store home: they bank as Ideas (using the commit path this PRD builds for goal 4), and the brief input of previously-deferred candidates extends to idea-banked deferrals so reviewers stop re-proposing them; idea *promotion* mechanics stay out of scope. `/improve`'s `(refactor)` deviation captures ride its own refactor commits per the existing ride-along rule, with the ordering mandated (append the capture before or with the commit that carries it) and a pending-store-edits check at its merge offer committing any straggler — the last capture can't be left carrier-less. `/retro` gains the same gated commit for its close-out edits (synthesized retro, PRD flip, pointer removal, late-stage ticket deviations, minted ADRs), then a gated PRD→default-branch merge per the configured merge convention — and its already-`Done` refusal becomes merge-aware: a `Done` PRD whose branch isn't an ancestor of the default branch gets the merge re-offer, not the closed-chapter refusal (the last gate in the lifecycle must be re-enterable, or one declined merge orphans the PRD forever). Re-entry generally: a close-out skill that finds its own half-applied state — store-artifact-path dirt plus the close-out status already flipped in the tree — resumes at the gated commit instead of refusing (neither the already-`Done` refusal nor the preflight may misread an interrupted close-out). Close-out commits stage enumerated paths, never `-A`. The close-out recipe's three synced copies (`/done`, `/next-ticket` recovery, `/retro`) change together. The store docs' ride-along rule is amended: end-of-lifecycle flips are committed as part of close-out; `/next-ticket` step 6's copy of the ride-along rule is reconciled with the amended text.
- **`/retro` precondition** *(files store only)*: refuse to rewrite the running retro until it is committed, making the "preserved in history" claim actually true. Notion has no commit to demand — its equivalent guarantee is page history, already claimed by the skill; the precondition is files-only prose.
- **Planning-phase convention codified across the planning chain** — its knowledge-layer prefix ends at the detail-stage `/grill-me`; the chain hands off to the lifecycle layer at `/to-tickets`, which owns everything git: `/next-prd` hands off to a high-level `/grill-me` (not directly to `/to-prd`), and `/to-tickets` ends by cutting the PRD branch from the default branch (resolved per the diff convention's base-resolution rule, so the cut point and `/retro`'s eventual diff base come from one procedure) and — files store — committing all planning artifacts (PRD, tickets, active pointer, grill-minted Glossary/ADR edits) as the branch's first commit; in notion the bootstrap is the cut plus the existing `Branch`/`Diff base` property writes, no commit. This resolves the review's chain contradiction. Ticketing is serialized; drafting is not: `/to-tickets`' ending (the `Open` flip + activation + cut + planning commit) requires that no other PRD is active or unmerged and that the session is on a clean default-branch checkout — refusing loudly with instructions otherwise (this also makes the store's single-active invariant enforceable instead of stealable). `/to-prd` and `/grill-me` stay runnable from any checkout: a draft PRD is untracked and survives switches; mid-flight Glossary/ADR edits ride the current PRD's branch, which is the already-accepted cross-PRD contract. The active pointer's content is pinned while we're in there: the PRD *directory name* (`<NNN>-<slug>`), not the bare slug, cited identically by every writer and reader. Branch-first placement makes two reads branch-aware to stay correct from any checkout: PRD numbering globs directories *and* `prd-*` branch names (local + remote) so an in-flight PRD's number can never be reissued from main's empty view, and any skill about to conclude "no PRDs / no active PRD" first checks for unmerged `prd-*` branches and names them ("PRD 001 appears in flight on `prd-001-…` — you may be on the wrong checkout") instead of proceeding on the empty view. Branch-first placement is deliberate: the default branch never carries a PRD's active-form docs, so a mid-PRD pivot or abandonment is one clean move — the `_abandoned/` relocation commits on the PRD branch and merges in preserved form. Main-visibility of planning artifacts is eventually-consistent at PRD close, same as every other store edit. The bootstrap stays a gated offer (gates are the workflow's deliberate stopping points, handing control back between phases), with the decline stakes stated loudly: until that commit, the PRD, tickets, and pointer are untracked and ride only the working tree. `/next-ticket`'s lazy PRD-branch creation is removed entirely — the PRD branch must exist before `/next-ticket` runs; a missing branch is a refusal pointing back at the declined bootstrap, not a silent re-derivation of the cut. The pointed-at gate genuinely re-runs: `/to-tickets` gains a narrow bootstrap-only re-entry arm — an `Open` PRD with tickets but no branch is by construction an interrupted or declined bootstrap, so `/to-tickets` re-offers the cut-plus-planning-commit and nothing else. The one-shot rule is rescoped to what it protects: *ticket creation* is one-shot per PRD (frozen scope); the bootstrap is re-enterable until it succeeds.
- **A new diff-materialization convention — a `_shared/` reference doc with a plugin-shipped script as its core, not a registered skill** (PRD-local decisions: doc-plus-script over a skill because its only consumers are other skills and nothing needs user-invocability; script over prose because the review's diff findings are all procedure-fidelity failures, and a script cannot skip a preflight). Division of labor: the invoking skill resolves the store-dependent inputs — `<base>` and `<head>` per store and per scope (ticket-scope: ticket branch vs PRD branch; PRD-scope: PRD branch vs recorded Diff base in notion / resolved default branch in files) — and passes them as arguments; a script cannot read the store. The script owns everything git-deterministic: validates the passed refs (both exist, a merge-base exists, and head is not an ancestor of base — catching reversed arguments and disjoint histories loudly instead of producing a silent wrong diff; base having *advanced* is never a refusal — divergence is exactly the case merge-base three-dot semantics exists for), enforces merge-base three-dot semantics, preflights branch/tree/emptiness with distinct exit codes (dirty means *tracked modifications only* — legitimate untracked planning artifacts never wedge a close; refusals print the offending paths), scaffolds the scratch directory's deny-by-default `.gitignore` if absent, and writes the scratch diff artifact at the stable path the fact-checker agent body names (`.pirr/diff.patch`). The shared doc also names a files-store consequence of the close-out commits: diffs legitimately include store-artifact hunks (committed deviations, retro entries, status flips), and the fact-checker/reviewer briefs label them as planning artifacts, not reviewable code. `/done`, `/retro`, and `/refactor` run the script per the shared doc instead of carrying their own git prose. `/next-ticket` is not an invoker: its branch cut cites the same base-resolution convention (so the cut point and the eventual diff base can't disagree), but its dependency-reachability check stays as its own single-command prose — the script stays single-purpose.
- **Cut the `strategy` axis entirely** — not just the `stacked` value: remove the key from setup's settings template, STORE.md's config example and branching-strategy prose, the plugin CONTEXT.md's Config entry, and `/next-ticket`'s strategy read and ask-once prompt (`/done`'s and `/improve`'s stacked-mode diff prose disappears wholesale into the diff convention; no README carries branching-strategy prose — verified, nothing to cut there); serial becomes the unconditional, unnamed behavior and `[branching]` survives only as the home of the `merge` convention key, which `/retro` now also reads — register it in the template's consumer comment (PRD-local: cheap to reverse; the scenario stacking served belongs to the Work workflow, which ships its own config). Setup's refresh path tolerates and ignores a stale `strategy` key in existing repos rather than erroring.
- **Spike/idea commit offer commits where you stand** *(files store only — notion banks are rows with nothing to commit)*. `/to-prd`'s gated offer commits the banked file on the current branch — no checkout ceremony. Every branch flows to main, and ideas/spikes aren't PRD-active-form docs, so the clean-main placement rule doesn't apply; a mid-ticket bank rides the ticket branch and reaches main at PRD close. That rationale stays in this PRD deliberately: it leans on the Personal workflow's close-out mechanics and must not migrate into `/to-prd`'s store-neutral, lifecycle-agnostic prose (ADR 0001) — the skill gets only the bare gated offer.
- **Design constraint carried from ADR 0001:** knowledge-layer skills stay lifecycle-agnostic — nothing in this PRD may make them assume the Personal workflow's close-out mechanics.

## Modules touched

- **Lifecycle layer**: `/done`, `/retro`, `/next-ticket`, `/refactor`, `/to-tickets` — close-out commit/merge gates, preconditions, planning-phase branch cut, `/next-ticket`'s lazy-creation removal and PRD-branch-exists precondition.
- **Knowledge layer**: `/next-prd` (hand-off chain), `/to-prd` (spike/idea commit offer).
- **New shared convention**: diff materialization (`_shared/` reference doc + plugin-shipped script), consumed by three lifecycle call sites (`/done`, `/retro`, `/refactor`); `/next-ticket` cites only its base-resolution convention.
- **Shared reference docs**: the store doc's commit rules and config example, the retro format's precondition, the plugin CONTEXT.md's Config entry, the README's workflow chain, and the Glossary header's "prose-only" self-description (stale once the bundled script ships — amend alongside it). The fact-checker/reviewer brief change (planning-artifact hunk labeling) is additive-only — the nine reviewer agent bodies do not change.
- **Setup**: the settings template (strategy cut).
