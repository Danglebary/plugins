# Reviewer trust boundary

## Problem

The plugin-shipped reviewer agents discover the authority they defer to from the working tree, which at review time is the diff's head. `standards-reviewer`'s precedence rule lets a documented repo standard silence a baseline smell; `spec-conformance` judges a diff against a spec source (the ticket's Goal/Acceptance, the spec's Approach) that it grounds against the same head tree. In both, the authority and the code under review come from one post-diff state — so a single diff can both trip a rule and rewrite the authority that would catch it. A change that adds an over-long handler and appends a `CLAUDE.md` line blessing that shape reads its own blessing back and stays silent; a ticket branch that rewrites its own Acceptance criteria is judged conformant against the rewritten bar.

The weakness is latent in the Personal workflow, where the diff author is the trusted user — ticket 005 (spec 001) surfaced it and deferred it on YAGNI grounds. But the reviewer agents and the `/done` close-out pair are cross-plugin Knowledge-layer surface (ADR 0001), reused by the PR-based Work workflow whose diff author is an untrusted teammate. That plugin is now a live second consumer, so the weakness is baked into a reused API just as its riskiest consumer arrives. ADR 0005 records the decision to harden the shared surface in this repo rather than leave it to the Work plugin.

## Goals

- A blessing a reviewed diff introduces no longer silences a baseline smell in `standards-reviewer`; the un-silenced smell surfaces with the self-blessing flagged.
- `spec-conformance` renders its verdict against the frozen base contract, not a diff-rewritten one; a diff that modifies the contract it is judged against is surfaced for the user to confirm.
- The `## Deviations` section — legitimately authored on the ticket branch — is untouched by the conformance hardening.
- No reviewer agent gains git access or any new tool surface; git mechanics stay in the dispatcher per the diff-materialization division of labor.
- Neither agent's load-bearing output contract changes — findings and verdicts flow through the existing parsed sections.
- The Work workflow inherits a hardened shared surface without this spec touching the Work plugin.

## Non-goals

- Hardening reviewer agents that do not defer to a rewritable authority (the language experts, `qa-engineer`, `security-engineer`, `software-architect`, and the rest). Only the two agents with explicit authority-deference are in scope.
- Any base-tree snapshot, worktree, or checked-out base tree — and no git tool for the agents. The agents still see only the diff artifact and their brief; the base contract they judge against is built dispatcher-side by the tamper-script's targeted `git show <base>:<path>` reads (individual files at an already-resolved ref, not a materialized tree), per the diff-materialization division of labor.
- Any new output section or heading in either agent; the parsed contracts stay fixed.
- A new principle/reference doc for the stance. The rationale lives in ADR 0005; each site states its own rule and cites it.
- The Work plugin's own dispatch-layer defenses. It may still base-pin its briefs for stronger mechanical guarantees; that is its concern, not this spec's.

## Approach

Governed by ADR 0005: an authority a reviewed diff touched is suspect — surfaced or judged against its base version, never obeyed as post-diff authority. The two agents need different remedies because one emits findings and the other a verdict, and because the agents are toolless the fix necessarily splits between agent bodies and the `/done` dispatcher.

**`standards-reviewer` — a caveat on precedence.** Its precedence rule that "a documented standard blesses a pattern and silences the smell" gains a caveat: a standard whose blessing the reviewed diff introduced or rewrote earns no override authority. Mechanically the agent checks the blessing against `.pirr/diff.patch` — if the line(s) carrying it appear as added lines (`+` hunk lines, not the `+++` file header) in a hunk touching the standard's file, the blessing is self-introduced and void. The test is **strict and line-granular**: *any* `+` touching the blessing line voids the override — a pure rewrap trips it too, a cheap over-flag deliberately preferred over a gameable meaning-level test on a security boundary — while a blessing the diff leaves untouched keeps its authority even if the same file is edited elsewhere. The smell it would have silenced is therefore never silenced — it resurfaces as an ordinary candidate through the existing output list, with the self-blessing noted in the mandatory Judgment-call field (citing the standard's home) so the reviewer relaying it sees why it was flagged. The existing Source field flips to `baseline: <smell>` on its own grammar when the override is voided, so Source and Judgment-call together carry the flip and its reason — no new field or louder marker, whose alarm register would mis-signal what ADR 0005 treats as a usually-benign honest introduction resolving to a one-line confirm. A blessing added *outside* the review's `base...head` range is pre-existing to this diff and honored — the cross-diff accumulation attack is the agent-judgment-robust limit ADR 0005 scopes out. The agent derives all of this from the diff artifact it already reviews hunk by hunk; no dispatcher brief change and no output-contract change.

**`spec-conformance` — base contract plus a dispatcher-side alarm.** Two layers. `/done` inlines the frozen Goal/Acceptance (and the spec's Approach) from the base it already resolves (the spec branch) rather than the head version, so the conformance verdict judges against the contract as frozen; a diff built to rewritten criteria but not the base criteria then surfaces through the existing sections (missing/partial, or scope creep). Separately, `/done` mechanically surfaces when the diff modified the contract — the ticket's Goal/Acceptance or the spec's Approach — as a confirmation the user must acknowledge, with the legitimately diff-authored `## Deviations` exempt. The agent's own change is narrow: for the three guarded sections it must treat the inlined base copy as authoritative rather than re-grounding its citations against the possibly-rewritten head ticket file or head `spec.md`, inverting today's "cite the file, not the inline copy" instruction for those sections only. The handoff that makes this possible: because a toolless agent's Read/Grep sees only the head tree, the script's base-text output carries each line's **absolute base line number** (a `grep -n`-equivalent over the base file, section-filtered), and the brief instructs the agent to cite those numbers as-is — so citations stay the existing `file:line` shape into the real ticket/`spec.md` path, just resolved against the frozen base version, with no new citation syntax and no output-contract change. The agent's `looks-wrong` verification and pre-existing-code checks keep using Read/Grep over the working tree; only the spec-source citation grounding of the three guarded sections flips to the inlined base copy. The base contract is inlined into the *shared* brief both close-out agents receive; the `deviation-fact-checker` is unaffected by the base-for-head swap, because it audits `## Deviations` against the diff and never judges against the Goal/Acceptance criteria as a bar.

**Base resolution reuses what exists.** Both the diff artifact `standards-reviewer` reads and the contract `/done` inlines derive from the base the diff-materialization convention already resolves (the spec branch for ticket scope). No new base concept is introduced.

**Documentation.** Each site states its own rule and cites ADR 0005 for the shared rationale; no new principle doc — the three mechanisms do not share operative content, only the why the ADR already holds.

**Tamper-check mechanization — a shipped dispatcher-side script.** `/done`'s contract-tamper surface is a small script in `scripts/` alongside `materialize-diff.sh`, not skill prose. Applying ADR 0002's placement test: the check is a hot-path *procedure* (section-aware, multi-step), not a coarse classification, so mechanizing it serves the placement test's own procedure-fidelity goal — a script call is a single fidelity-safe instruction on the hot path *and* cannot skip a step, the failure mode a security surface most needs to avoid. Given `<base> <head>` and the guarded section names, the script emits the base section text with each line's absolute base line number prefixed (feeding conformance's citation grounding) and a tamper flag computed by extracting each guarded section from the base and head versions and comparing them; the `## Deviations` exemption falls out because only guarded sections are ever extracted. `serialize-preflight-script` is the adjacent precedent — a multi-step git preflight pulled into a script + bats.

Detection is **section-granular via extract-and-compare**, not hunk-attribution. The script reads the base and head versions directly (`git show <ref>:<path>`), extracts each guarded section by its canonical heading (`## Goal`, `## Acceptance criteria`, `## Approach`) from that heading to the next `## ` or EOF, and compares — the tamper flag is a per-section boolean ("did the contract change base→head?"), which is all the "was it rewritten?" question needs; line-granularity is `standards-reviewer`'s job, not this one. Reading the base directly sidesteps the patch-parsing fragility ADR 0005 already rejected for the base-reconstruction alternative (hunks spanning section boundaries, context-line ambiguity). Heading drift **fails safe**: a renamed or removed guarded heading yields an empty head extraction that differs from the base and so surfaces, rather than silently passing; an unrelated inserted section does not false-positive, because extraction keys on the guarded heading, not on line ranges. (This leans on the acceptance checkboxes staying untoggled, which they are today — the `enforce-or-remove-acceptance-checkboxes` idea tracks making that explicit.)

## Modules touched

- **`standards-reviewer` agent** — the precedence-rule caveat and the Judgment-call note for a diff-introduced blessing; strict line-granular `+`-line derivation from the diff artifact.
- **`spec-conformance` agent** — the citation-grounding inversion in its inputs/verification-scope section: the inlined base contract (Goal, Acceptance, Approach) is authoritative and carries base line numbers to cite, rather than re-grounding against the head ticket file / head `spec.md`.
- **`/done`** — inline the line-numbered base contract (Goal/Acceptance/Approach) into the close-out brief; add the mechanical contract-tamper surface with the `## Deviations` exemption.
- **`scripts/` (new dispatcher-side script + bats)** — extract-and-compare over the base/head versions of the guarded sections: emits the line-numbered base section text and the per-section tamper flag; `/done`'s only consumer.
- **Glossary (`CONTEXT.md`)** — *Reviewer trust boundary* (added during the grill).
