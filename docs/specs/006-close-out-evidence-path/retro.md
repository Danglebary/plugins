# Retro: 006 — the close-out evidence path

## Ticket 001 — Untracked implementation files stop a close-out

**Outcome**: Extended

Designing the preflight against the repo's actual resting state rather than the ticket's imagined one changed the answer: six untracked banked ideas sat in the tree the whole time, which killed the stash-widening approach (ceremony plus a crash window on every routine close-out) in favor of a report-then-acknowledge round trip. A preflight added to a shared mechanism acquires callers nobody enumerated — the new exit fired inside `RECOVERY.md`'s resume recipe, and the deviation entry declaring that file "untouched" recorded the non-edit while missing its consequence, which is the shape a non-edit's blast radius always takes. The close-out pair earned its keep here: four real defects, two of them leaving an acceptance criterion partial, none of which the implementing session saw.

## Ticket 002 — A guarded section is compared in full and in isolation

**Outcome**: Extended

Chasing a bats line number that contradicted a hand trace found the larger bug: on bash 3.2 a failing `[[ ]]` inside a function trips neither `errexit` nor the ERR trap, so only a test's final command decides pass/fail and 26 of 67 assertions across both suites never ran — the guard-that-reports-all-clear failure this spec exists to close, sitting in the tests that were supposed to be checking for it. The lesson generalizes past bats: an assertion is infrastructure, and infrastructure that has never been observed failing is unverified regardless of how many times it has "passed". Two fence defects collapsed into one fix once fence state gated the start condition as well as the stop, which is why AC1 and AC2 needed no separate mechanism; and the close-out pair caught a narrowing the plan gate had approved but neither the deviations nor any fixture recorded — approval at plan time does not survive as evidence, only a test does.

## Ticket 003 — The evidence rules get one home

**Outcome**: Exact match

An ADR fully settled during grilling turned implementation into transcription: the plan gate carried only naming and inclusion decisions, and the diff produced zero deviations — the cheapest close in the spec so far, which is what front-loading design into the ADR buys. The deferred resolve-by-phrase steer proved itself immediately: two of the six anchors it covered had shifted *again* since the steer was written, confirming that a line number cited across a spec branch's lifetime is stale the moment a sibling ticket lands, and only the quoted phrase survives. Homing the rules ahead of their application leaves the format doc deliberately leading the live agent bodies — a planned drift window the sequencing (003 before 004/005) prices in rather than avoids.

## Ticket 004 — Every agent can report what it could not check

**Outcome**: Extended

Two verification tiers caught what the other could not: the mechanical check passed 15/15 on every probe while the decorrelated re-read found two real gaps behind those passing counts, and the close-out fact-check then caught an error in the re-read's own report — a "12 non-owning bodies" count that silently excluded the one body that differed. Each tier's blind spot was the next tier's finding, which is the argument for stacking them rather than trusting any one. The reload seam turned out to bound what a corpus-editing session can verify about itself: the register's failure arm fired against pre-edit bodies and proved nothing, and the probe that established this — asking the agent to quote its own output contract — is the cheap, general test for whether a dispatch served the tree you just edited. A frozen acceptance criterion can also be factually wrong about the repo: the six-member sync-set it names has four carriers, two of which never carried the phrase at all, so the criterion's operative half was satisfiable while its premise was false — and ADR 0006 repeats the same false premise.

## Ticket 005 — A lens that cannot resolve refuses instead of being improvised

**Outcome**: Divergence

**Dispatch**: close-out pair — both returned.
**Dispatch** (refactor): 7 reviewers — all returned.

An evidence mechanism can be defeated by its own ordering: the dispatch record was composed *after* the Resolution preflight, so `unresolved` — the one state reachable only on a preflight failure — could never be recorded, because the refusal ended the run before the record existed. That is the doc's own "register behind a halt instruction" anti-pattern one layer up, and no grep for presence finds it; only re-reading the shipped steps for *reachability* did, which argues that prose acceptance criteria need a control-flow read, not a keyword sweep. The close-out pair earned its keep against a diff whose author had already re-read it twice: the conformance agent refuted a decision from an accepted ADR's own text (my "the callout has no receiver" premise, against ADR 0008's "no dispatching-skill edit is required"), and the fact-checker found a deferred steer silently dropped — both classes a self-review had missed, and both cheaper to fix at close than after merge. Canon written ahead of implementation keeps drifting in the same direction: `EVIDENCE-PRINCIPLE.md`, `README.md`, and the Glossary each described a dispatch layer that did not exist, and the Glossary — which both dispatching skills inline verbatim into briefs — would have taught executors the three-state record this ticket argued against.

**Owed behavioral observations — still owed, deferred to this ticket's `/refactor` pass.** Neither fired here, for the reason ticket 004 documented: **skill prose shares the agent-body reload seam.** Confirmed directly — the `/done` text loaded into this close was the pre-edit version (no Resolution preflight at step 3, the old two-state sentence at step 5), while the edited version sat committed on the branch. This extends ticket 004's finding from `agents/*.md` to `skills/**/SKILL.md`, and it retires the "assumed, unverified" flag this ticket's plan carried on exactly that question. The close was run against the shipped contract anyway (composing the record, pinning both types, preflighting both names) since the loaded text forbids none of it — but a preflight-refusal fixture executed by pre-edit prose would prove nothing. Both remain paired for one post-reload batch: (1) dispatch with a deliberately unresolvable `subagent_type`, observe the *skill's* named refusal, and confirm the record marks the lens `unresolved` — note the tool boundary's hard-error is already confirmed (fired twice, 2026-07-19 and this ticket's research pass) and is **not** what this owes; (2) ADR 0008's four-arm planted-instruction fixture. Both close-out agents returned registers this session despite the seam, so the pair's bodies were the post-reload ones.

**Owed behavioral observations — BOTH DISCHARGED by ticket 005's refactor pass (post-reload).** The reload probe passed first: `/refactor`'s loaded step 2 carried "Compose the dispatch record from the manifest names", the phrase absent from the pre-edit prose, so this session held the edited skill text — the first point in this spec where a dispatching skill's own new prose could be executed rather than only shipped. **(1) The Resolution preflight's refusal arm fired.** A deliberately unresolvable name added to `docs/reviewers.md` produced the *skill's* named refusal with the record marking that lens `unresolved`, and it fired **before any dispatch** — no `subagent_type` reached the tool boundary, which is the distinction the steer said was still owed (the tool erroring was already confirmed twice and is not this). Each instruction reported once, by its owner, zero convergence inflation. Arm 3: both close-out agents emitted the flagged callout — twice each, one per instruction — fenced longer than the quoted text, ahead of the finding sections, and kept out of the parse contract by name. Arm 4: across twelve dispatches (seven on the real diff, five on the fixture) no lens flagged ordinary imperative prose, and `security-engineer` stated the boundary test unprompted — "the addressee shift marks the boundary."

**The `**⚠ Planted instruction:** none found.` sentinel — cause diagnosed, and it is not under-specification.** Ticket 005's close recorded both pair agents emitting that forbidden sentinel before self-correcting, and inferred the rule was under-specified in the bodies. It is not: each pair body states it **three times** — in the inputs position ("its absence is not a claim"), in the output format ("omit it entirely when you found none"), and inline in the template ("← only when one was found; omit otherwise"). Restating a thrice-stated rule cannot be the fix, so the corpus-wide sweep of all fifteen bodies that finding seemed to demand is the wrong remedy. The likely cause is structural, and this pass supplies the control: the callout occupies **position 1** in the pair's return template — a conditional field placed ahead of the scan that conditions it, so an agent composing top-down reaches the slot before it has earned the right to fill it. The reviewers have no leading conditional slot and **zero of seven** emitted a sentinel. That is the doc's own "register behind a halt instruction" anti-pattern inverted, and it argues the fix is positional (show the callout-absent shape as the template's default) rather than more prose.

## Ticket 006 — Every test assertion can fail

**Outcome**: Extended

**Dispatch**: close-out pair — both returned.

An assertion mechanism cannot be verified by positive cases: a helper stubbed to `return 0` passes every test that asserts success, so only the negative twins pin it — this ticket's own question asked one level up, and the close-out pair caught the new suite failing to ask it of itself. The Goal's account of *why* `[[ ]]` fails was wrong in both its mechanism and its arithmetic while its conclusion held exactly, which is survivable in a ticket and not in the comment AC5 required, since that comment is what a future contributor reasons from rather than the ticket nobody reopens. Both lenses ran with Grep and Glob broken and said so in their registers instead of returning quiet absence claims — this spec's evidence contract paying out on a defect in the tooling rather than in the work.
