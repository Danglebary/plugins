# Retro: The close-out evidence path

## Problem — Extended

The three named defects held exactly as framed, and each was closed where the spec said it would be: the never-staged file that vanishes from both the diff and the close-out commit (ticket 001), the tamper extractor that compares widened or truncated text (ticket 002), and the agents that cannot say what they did not check (tickets 003–005). The Problem's mechanism analysis survived verification down to the boundary it claimed — staged-but-uncommitted trips exit 5, never-staged trips nothing. What the framing missed is that the same failure shape it describes was sitting in the repo's own test suite: 17 of 54 `.bats` assertions could not fail on the only bash macOS ships, so the guard checking for guards-that-report-all-clear was one. That became ticket 006, a sixth ticket in a spec that locked with five, and it is the strongest evidence for the Problem's thesis rather than a departure from it.

## Goals — Extended

All six goals shipped. The one worth naming is the third, because it is the only goal in the spec whose satisfaction could not be established by reading the diff: every claim-making agent gained the **Partial verdict** register, and the register's failure arm was then observed firing seven times against a real brief with unforced gap entries (ticket 004), the Resolution preflight's refusal arm once before any dispatch reached the tool boundary (ticket 005), and ADR 0008's four reporting arms across twelve dispatches (ticket 005). The spec's own lesson — infrastructure never observed failing is unverified — was applied to the spec's own output. The seventh, unplanned goal came from ticket 006: an assertion that cannot fail is the same defect one layer down, and a helper stubbed to `return 0` still passes every positive-path test, so only the negative twins pin the mechanism.

## Non-goals — Exact match

Every fence held. Verification tiers stayed rejected, the "what I read" field never appeared, the gate-doctrine audit and progressive-disclosure restructure stayed banked, the two forks stayed unreconciled, and the dispatch record shipped as an attestation rather than a mechanism. The general sync-set guard held too — and this close measured its cost: the spec-scope fact-check found the artifact-map enumeration grown from five carriers to seven (ticket 001) and the Reviewers-manifest sole-reporter annotation propagated to `docs/reviewers.md` but not to the `/setup` default set that generates it (ticket 004). Both are exactly the drift the fenced-out harness would catch. The fence was correct — that harness is unsolved design — but four measured drifts now sit behind the banked idea instead of one.

## Approach — Divergence

The sequencing argument held: one real dependency edge, the lifecycle-skill edits in a single ticket, the corpus sweep as one ticket rather than fifteen. What diverged is what the Approach assumed it could consume unchanged. `EVIDENCE-PRINCIPLE.md` was written during grilling and meant to be transcribed, but named three dispatch-record states in one paragraph while mandating a fourth elsewhere in the same doc — so ticket 005 edited its own source of truth and shipped four states against an acceptance criterion naming three. The content-channel plank was re-keyed mid-spec from material class to agent class (ticket 004's refactor pass), which the Approach never contemplated, producing a new principle doc and ADR 0008. And the record's keeper set contracted: the Approach assigns `/retro` a dispatch record, ticket 003's refactor pass settled the keepers as `/refactor` and `/done` only, and `/retro` ships none — the spec is tamper-guarded, so the divergence lives on ticket 005 rather than in the line.

## Modules touched — Divergence

The list under-counted in both directions. Ten modules were named; the branch touched those plus `REVIEWERS-FORMAT.md`, `refactor/INTERFACE-DESIGN.md`, `plugins/pirr/CONTEXT.md`, `docs/reviewers.md`, `.pirr/settings.toml`, `RECOVERY.md`, a new `CONTENT-CHANNEL-PRINCIPLE.md`, a new `scripts/test_helpers.bash` with its own suite, and a root `CLAUDE.md`. Each expansion has a recorded reason — a stale Glossary that both dispatching skills inline verbatim into briefs (ticket 005), an unspecified `subagent_type` in a doc-design dispatch (ticket 005), a clause with no shipped home (ticket 004) — and the pattern across them is that a change to a contract keeps reaching the doc that teaches the contract, which the Modules list never modeled. In the other direction, one listed deliverable was deliberately not built: `/retro`'s dispatch record.

## Refactor — Extended

The refactor passes did the spec's heaviest architectural work, not its cleanup. Ticket 001's pass produced ADR 0007 (authorship is scoped to the close, not the invocation) after finding that its own resume recipe would route a resuming run into an arm that drops the crashed run's minted ADR — this spec's silent non-ship, one layer up. Ticket 003's pass settled the dispatch record's seam and keeper set before any of it was implemented. Ticket 004's pass homed the content-channel rule in a new principle doc with ADR 0008 behind it and re-keyed the reporting partition onto the axis that actually justifies suppression. Ticket 005's pass fired both owed behavioral fixtures and fixed the defect they exposed — a refusal that marked only the failing names, leaving seven resolvable-but-never-dispatched lenses with no state. Ticket 006's pass made the new assertion module stop trusting its callers. The recurring shape: a pass over a ticket's own diff finds the thing the ticket's author had already re-read twice.

## Cross-cutting

- **The reload seam bounds what a corpus-editing session can verify about itself.** Discovered in ticket 004 for `agents/*.md`, extended in ticket 005 to `skills/**/SKILL.md`: edited prose is as stale within the editing session as an unregistered new agent. The cheap general probe is asking the dispatched agent to quote its own output contract before trusting anything it returns. Every behavioral observation this spec owed was blocked once by this and discharged in a later session's refactor pass.
- **Frozen artifacts can be factually wrong about the repo.** Ticket 004's acceptance criteria name a six-member sync-set with four carriers, two of which never carried the phrase in any form — and ADR 0006 repeats the same false premise. `spec.md`'s Modules-touched line assigns `/retro` a dispatch record it does not ship. Both are tamper-guarded, so the corrections live in Deviations. A frozen artifact protects a claim from tampering, not from being wrong.
- **Line-number anchors rot within a single spec branch's lifetime.** Ticket 001's diff moved three of ticket 005's anchors and two of ticket 003's; the deferred steers that re-resolved by quoted phrase survived, the ones citing `file:line` did not. Adopted mid-spec and it paid immediately.
- **A count used as a load-bearing argument needs a mechanism, not a sentence.** Ticket 001 declined to grow the artifact-map sync-set *because it had five members*, shipped that number into a live contract doc, and the same spec grew the set to seven. Four sync-set drifts are now on record behind one banked idea.
- **The spec that shipped the dispatch record has no record for four of its own six tickets.** The field arrived in ticket 005, so entries 001–004 carry none — the exact "which lenses ran is legible after the session ends" gap the record exists to close, visible in the artifact that introduced it. Not a defect to fix retroactively; an illustration of why the rule needed writing.
- **Two verification tiers each caught what the other could not.** The mechanical check passed 15/15 on every probe while the decorrelated re-read found two real gaps behind those passing counts, and the close-out fact-check then caught an error in the re-read's own report — a count that silently excluded the one body that differed. Each tier's blind spot was the next tier's finding.
