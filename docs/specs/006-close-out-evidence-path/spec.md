# The close-out evidence path

## Problem

Every ticket closes by handing a diff to analytical agents and acting on what they report. Three defects sit on that path, and each one lets a close-out complete while reporting more confidence than the evidence supports.

**The diff can be silently incomplete.** `materialize-diff.sh` refuses on a dirty tree, but its preflight is `git status --porcelain --untracked-files=no` — tracked modifications only. That is deliberate, stated in `DIFF-MATERIALIZATION.md:52` so legitimate untracked planning artifacts (a drafted spec, a banked idea) never wedge a close-out. The rule merges two unlike things: a banked idea and a **never-staged** implementation file. Fired against a scratch repo, the boundary is exact — a staged-but-uncommitted new file reports `A ` and trips exit 5, while a never-staged one reports nothing, the script exits 0 with a reassuring `1 file(s)` summary, and the new code is absent from `.pirr/diff.patch`. The consequence is worse than "unreviewed": `CLOSE-OUT.md:7` enumerates the close-out commit from store-artifact paths only, so the file is never committed either. The feature silently does not ship. `IMPLEMENTATION-LOOP.md:26` rests its staging argument on the claim that *"any left unstaged stays tracked-dirty and trips the same misroute"* — false in both directions: an unstaged *modified* file leaves the tree dirty in an implementation path, so `/done` never reaches the interrupted-close-out misroute at all (it hits exit 5 and correctly refuses), and an unstaged *new* file trips nothing. Same conclusion, wrong mechanism, opposite severities. The same hole reaches `/retro`'s spec-scope diff, and `/retro:30` already carries a hand-written patch for exactly one instance of it.

**The tamper guard can compare the wrong text.** `contract-tamper.sh` exists so a reviewer never obeys a contract the reviewed diff rewrote (ADR 0005). Its `section()` extractor keys on `$0 == h` and treats any `^## ` line as a boundary, with no awareness of fenced code blocks. Two independent triggers follow. A fenced heading *inside* a guarded section truncates capture there, so a rewrite of the trailing body reads `unchanged` — but only when the fence already exists at the base ref, which makes it passive or cross-ticket, never a single-diff attack. A *repeated* heading makes capture **additive**: `$0 == h` is evaluated on every line and re-enables capture, so both sections concatenate and the widened text is handed to the conformance brief as authoritative base contract. The second trigger is fence-independent and survives any fix aimed only at fences. For a single-user repo the realistic case is passive rather than adversarial — a spec's `## Approach` containing a fenced markdown example, which this corpus writes routinely — so this is a correctness defect first and an injection vector second. Two reviewers converged on the fence half during spec 004 and it was banked; the script's other fail-open was closed in that spec's refactor pass, so the surrounding hardening is already in place. No test in `contract-tamper.bats` touches fences or repeated headings.

**Agents cannot say what they did not check.** `/refactor:62` requires per-area *"checked, clean"* lines because *"silence is indistinguishable from not-looked."* All thirteen reviewer agent output contracts end *"output `_No <lens> candidates._` and stop"* — a literal halt, stated inside the agent's own system prompt and reinforced by `Don't pad` in Anti-patterns, against one sub-bullet of a dispatch brief. Two contradicting instructions reach one executor and the agents' side has won for about five weeks; three independent reviewers converged on it in the 2026-07-08 deep-dive and one adversarial verifier confirmed it, with a fix direction (*"pick one side and change all nine agents plus the brief together"*) that was never taken. The reviewer set has since grown from nine to thirteen. The failure it conceals is on record: spec 002's retro documents a newly authored agent that *"isn't a registered dispatch type until the plugin reloads,"* so the first live close-out ran it inlined into a generic agent — a lens that did not run, producing output indistinguishable from one that did. `/done:65` already depends on this distinction in one place, where an absent `## Deviations` section reads "nobody checked" and an explicit `_None._` reads "checked, clean" — but that sentence names `/retro` as the consumer relying on it, and `/retro` never reads section absence. The corpus states the rule once, and states it with a false justification.

A fourth gap rides with the third. `DIFF-MATERIALIZATION.md:66` requires injected-instruction scrutiny of planning-artifact hunks; nothing says the same of code. An instruction-shaped line in a comment or docstring reaches every agent that reads a diff with no rule that it is data to fact-check rather than a directive to obey. ADR 0005 defended the authority channel and left the content channel open.

## Goals

- An implementation file that was never staged stops a close-out instead of vanishing from it, and the staging contract's safety argument matches what the mechanism actually guarantees.
- A guarded contract section is compared in full and in isolation — no fenced content truncates it, no repeated heading widens it — so the base text handed to a reviewer is the contract and nothing else.
- Every claim-making agent can report a surface it could not check, and cannot stay silent about having checked; the skill that dispatched it refuses before dispatch when a lens cannot resolve, and records which lenses ran.
- An empty search cannot become a finding of absence without a positive control.
- The checked-versus-unchecked rule has one home, cited rather than restated, and the one place that states it today stops citing a consumer that does not exist.
- An instruction-shaped line reaching an agent — inlined in a brief or read from the working tree — is treated as data by every agent, and reported by exactly one.

## Non-goals

- **Verification tiers.** The documented-versus-fired distinction and its completing-residual bookkeeping are rejected (ADR 0006): every operation pirr touches is locally fireable.
- **A required "what I read" field on every finding.** Findings are billed only where a gap exists.
- **A general sync-set or manifest guard.** The banked harness's open question — how to declare a sync-set machine-readably — is unsolved design and stays out. This spec's sweep is checked instead by grep-verified enumeration plus a tier-decorrelated pass, per `002/retro.md:29`. The fence is around the *harness*, not around checking.
- **The gate-doctrine corpus audit.** ADR 0004's owed sweep is its own spec; this one adds no gates and re-classifies none.
- **Progressive-disclosure restructuring.** No skill is split into router and variants here.
- **Reconciling the two forks' evidence doctrines, and propagating any fix to `work-plugins`.** The Glossary record has been corrected — the Knowledge layer is forked, not invoked — but `work-pirr` ships the same untracked-diff hole and its own `EVIDENCE.md` in the tier vocabulary ADR 0006 rejects. Its ADR 0004 priced no-automatic-propagation, and reconciling a Knowledge-layer rule that is workflow-agnostic by definition is a decision that ADR did not price. Out of scope here.
- **Cross-diff blessing accumulation.** Still the agent-judgment-robust limit spec 004 scoped out.
- **A mechanized dispatch record.** Whether a hook receives the dispatched agent type is unverified; the record ships as an attestation. If the field exists, ADR 0006 is amended rather than superseded.

## Approach

**The diff gap is closed at the mechanism.** `materialize-diff.sh` gains an untracked preflight using `git ls-files --others --exclude-standard` — per-file paths, ignored files already excluded — rather than `git status --porcelain`, which collapses a whole new source subtree to a single `newdir/` the classifier cannot route. The script excludes `.pirr/` as its own scaffolding: the deny-by-default template whitelists `.gitignore`, so `.pirr/.gitignore` is permanently untracked-and-visible and would otherwise fire the new exit on every run. The new exit means *classify these*, not *refuse*; the invoking skill classifies three ways per `CLOSE-OUT.md:7`, which is already three-way and which a two-way split would contradict — implementation dirt refuses and is named, the invocation's own store artifacts proceed, foreign store artifacts proceed and are named. Classification stays in the skills so the artifact-map globs are not copied into the script. `DIFF-MATERIALIZATION.md`'s guarantee is restated to separate the two cases it merges, and `IMPLEMENTATION-LOOP.md`'s staging argument is corrected rather than strengthened — a false safety claim is worse than an absent one. Two existing tests pin the old behavior as intended (`materialize-diff.bats:115`, `:124`) and are rewritten, not extended; the acceptance criteria name them so the change does not read as a broken suite.

**The extractor becomes fence-aware at both conditions, and fails safe on ambiguity.** Fence state gates the start condition as well as the stop, so a fenced heading neither begins nor ends capture. Because that alone leaves the fence-independent trigger open, a heading matching more than once outside fences reports `changed` with no base body — the same fail-safe posture the script already takes at `:78-83` when a target resolves at neither ref. The bats suite gains fixtures for both triggers.

**The evidence contract is homed once and applied by attestability** (ADR 0006). A new principle doc under `_shared/` states the honesty rule, the partial-verdict register, the empty-read corollary, and the dispatch record; `AGENT-FORMAT.md` places the register inside the output-contract shape it already documents. The register's **contents are gap-only but its emission is mandatory**: no gap emits `_Full._`, so silence is off-contract rather than a clean result, and it is placed ahead of the halt instruction it would otherwise be unreachable behind. The close-out pair is included despite being the only parse-coupled agents — they carry the sharpest empty-read hazard — with their contract restated as three *finding* sections followed by the register, and a precedence line keeping findings' own caveats distinct from the register's record of unread surfaces. The empty-read corollary binds only where absence is the claim: a *missing* or *dropped* finding needs the pattern, the paths, and a control match proving the search resolved; unscoped it would cost *O(searches)* and repeat the failure that killed the enumerated form.

**The dispatch layer's weight is deterministic, not attested.** Firing the Agent tool established that an unknown `subagent_type` hard-errors and enumerates every registered type, that a successful return carries no agent identity, that a subagent cannot self-identify, and that an inlined degradation reproduces the output contract — so detection is available only *before* dispatch. `/refactor`'s existing resolution preflight is ported to `/done`, which has none and is where the recorded degradation happened. Both skills gain an anti-substitution rule in the shape the corpus already uses for the hand-rolled-diff refusal: a `subagent_type` that does not resolve means that lens did not run, and is never recovered by inlining. The dispatch record is written from the manifest before results arrive, persisted in the per-ticket retro entry rather than left in chat, and its emission is mandatory with gap-only detail — mirroring `_Full._`, because a record written only when something breaks makes absence meaningless. `/refactor`'s brief sheds the enumerated requirement, and its dispatch bullet is made explicit that the diff is inlined as content — passing the path would violate `DIFF-MATERIALIZATION.md:62`'s two-agent contract.

**The content channel is closed by splitting obedience from reporting.** Non-obedience is universal and free — a stance, not work — and sits in each body's inputs position, before the reading it governs. Reporting is owned by one lens: security for code, prompt for prompt artifacts. Universal reporting would be actively harmful, since `/refactor:68` feeds convergence into ranking and fifteen agents flagging one planted comment produces maximum consensus on a TODO. The clause covers both delivery paths — hunks inlined into a brief, and working-tree content an agent reads itself in the ad-hoc arm, which ships no diff artifact at all — and carves out ADR 0005 explicitly, so it never widens that rule's line-granular test.

**`/done`'s sentinel rule is rehomed and made true.** It moves to the principle doc as the general checked-versus-not-looked instance it is, correcting two errors: the states are three, not two (absent, the `_None yet._` placeholder from `TICKET-FORMAT.md:60`, and `_None._`), and the `/retro` consumer it cites does not exist. Rather than delete the claim, `/retro` gains it — which tickets were never fact-checked is the spec-scope form of which lenses never ran, and `/retro` is the merge layer for a spec as `/done` is for a ticket.

**Sequencing is by dependency, not by narrative.** Only one real edge exists: the diff repair precedes the agent-facing work, because installing an honesty contract over an input that can silently omit files is self-defeating. The tamper fix is independent of both — `contract-tamper.sh` reads only committed refs through `git show`, so untracked state cannot reach it. The lifecycle-skill edits land in a **single** ticket covering `/done`, `/retro`, and `/refactor` together; cutting them twice was the main cost of an earlier two-spec split and is avoided by keeping one spec. The agent-corpus sweep is one ticket, not fifteen, with the enumeration check covering every file the sweep touches — the agents plus `/done`, `/retro`, `AGENT-FORMAT.md`, both Glossaries, and the READMEs, since the "three sections" phrase is a sync-set across all of them.

ADR 0006 and both Glossaries were written during grilling and are already on disk; the tickets consume them rather than producing them.
