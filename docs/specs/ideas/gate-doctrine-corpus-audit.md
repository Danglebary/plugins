# Audit every gate in the corpus against ADR 0004's test

From a deep review of the `work-plugins` fork, whose spec 005 took the same consent-vs-ceremony test this repo minted as ADR 0004 and — instead of applying it case by case as each collision arose — applied it **uniformly across the whole corpus in one pass**, then homed the result as a single enumeration every other mention cites. ADR 0004 here was scoped to the collision that forced it: it classified six gates (the merge, the ADR decision, `/done`'s outcome label, and the refactor-or-merge fork as consent; the ticket-branch commit and the `/done` invocation as ceremony) and stopped there. The rest of the corpus was never swept. `/retro` carries 21 gate-shaped constructions, `/done` and `/refactor` 15 each, `/to-tickets` 12 — none of them audited against the test that now governs them, and ADR 0004's own Consequences section already names the prose sites as a sync-set awaiting exactly this refinement.

The fork's result is the interesting part: applied uniformly to an audience of one, **almost nothing survived**. Entry status flips, hand-off flips, terminal closes, and findings appends all shed their gates; exactly three gates survived, each on a rationale that has nothing to do with audience — the gate that **locks new scope into existence** (minting tickets), the gate over a **destructive edit to prose the user wrote**, and the gate on **a decision the preceding verdict does not entail**. Generalized, that is a derivable gate policy rather than a per-case judgment: *gate what creates new scope, gate what destroys information you authored, gate the decision the workflow's own state doesn't determine — auto-fire everything else.* This repo is permanently in that audience-of-one position, so the derivation applies here without translation.

The companion rule is what keeps this from degrading into an opaque agent, and it should land in the same pass: **un-gated never means silent**. Every shed gate's write is still stated aloud as old → new over a *fresh* read of the current state, with two pinned edge cases — already at the target state means state it, never re-fire; any other unexpected state means surface the contradiction and **end that transition, not the run** (everything already stood up stays stood up). Three lines of contract that prevent a whole class of "the skill blew up halfway through and I don't know what landed."

Two smaller pieces from the same fork belong in scope. **Declines are store-carried, not session-carried**: when a user says no to a gate, the refusal is written into the artifact as a suppress-only record, so a session that dies between the decline and the next step doesn't resurrect and re-offer exactly what was just refused. This repo has the identical problem across `/clear` and across the `/done` → `/refactor` → merge fork, and it already has the right vehicle — `### Deferred steers` proved that ticket-file records survive session boundaries where chat does not. And **preview-equals-fired**: what a composite gate displays must be byte-identical to what the confirmation actually fires, with no create firing merely to make a preview more literal.

The value here is concentrated and cheap relative to the restructure idea: it deletes real friction on the paths this workflow runs every day, it is grounded in an ADR this repo already accepted rather than importing new doctrine, and the fork has already done the derivation and stress-tested it across seven skills and seven reviewers. Open questions at promotion: whether the surviving-gate enumeration lives in `CLOSE-OUT.md` or earns its own `_shared` home (the fork's lesson is that cross-skill prose contracts get standalone homes, and this one binds every lifecycle skill); whether shedding a gate that ADR 0004 already classified as consent needs a superseding ADR or merely an amendment; and whether the decline record is a new `## Deviations`-adjacent subsection or extends `### Deferred steers`, which per TICKET-FORMAT.md is already the parking place for cross-session obligations.
