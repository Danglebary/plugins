# /grill-me has no write-back path for the spec it grilled

From spec 006's detail grill (2026-07-19), where the gap was hit directly. `/grill-me` updates two artifacts inline as decisions land — the Glossary ("don't batch Glossary updates until end-of-session") and ADRs ("mint ADRs inline as decisions land") — and the corpus treats both as load-bearing. It has no equivalent for the **spec**. A detail-stage grill runs against a `Drafting` spec, resolves the design tree against it, and ends with the spec file exactly as it found it. The twelve decisions from spec 006's grill left the spec's `## Problem` still carrying four claims the grill had refuted, an `## Approach` whose sequencing argument the grill had falsified, and a scope that had changed twice — and `/to-tickets`, whose input is the file rather than the conversation, would have cut tickets from the pre-grill design.

The sharp part is that the permission already exists and goes unused: `SPEC-FORMAT.md:26` states plainly that *"`/grill-me` and `/to-spec` may edit a `drafting` spec freely."* The skill is authorized to write and simply never does. Nor does anything downstream close the loop — `/to-spec` is documented as writing a *new* spec ("writes a new spec with Status `Drafting`", "synthesize from existing context only") with no in-place re-entry for an existing draft, so the detail stage has no sanctioned writer at all. Spec 006 resolved it by hand-editing the spec, which worked but is exactly the kind of unexecuted prose step this repo has repeatedly found unreliable.

Fix shapes worth weighing at promotion, since they are not equivalent. **Inline, mirroring the Glossary discipline**: each resolved branch edits the relevant spec section immediately, which keeps the record consistent mid-grill and survives a session that dies halfway — but rewrites `## Problem` prose repeatedly and risks churn on branches later reversed (this grill split scope, then merged it back). **At the self-check**: one synthesis pass over the five sections once the tree is resolved, cheaper and quieter, but it reintroduces the batching the Glossary rule exists to forbid and is lost entirely if the session dies. **Delegate to `/to-spec` by giving it a documented re-entry** that rewrites an existing `Drafting` spec in place rather than minting a number — arguably the cleanest seam, since synthesis is already that skill's whole job, but it makes the detail stage a three-skill chain.

Two further questions the fix must answer. Whether the write-back is gated (the spec is the user's scope document, and silently rewriting their `## Problem` mid-conversation is a destructive edit to prose they authored — the gate-doctrine idea's own surviving-gate test would likely say yes). And whether it applies at the high-level stage, where by definition no spec exists yet and there is nothing to write back to — suggesting this is a detail-stage-only mechanic and should be stated as one. Adjacent to the banked `grill-me-stage-handoffs` idea: that one gives `/grill-me` a forward hand-off it lacks, this one gives it a write-back it lacks, and both are terminal-behavior gaps in the same skill — worth grilling together to decide whether the detail stage ends by writing, by recommending, or both.
