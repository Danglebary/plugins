# A commit-time guard for manifest resolution and prose sync-sets

From ticket 005's refactor pass (qa-engineer). The plugin has no automated check that the machine-checkable invariants in its own prose actually hold — a class of drift caught today only by a human reviewer or by an end user hitting a runtime refusal:

- **Manifest name → agent-file resolution.** Every `pirr:<name>` in `docs/reviewers.md` and in `/setup`'s default list should resolve to a `plugins/pirr/agents/<name>.md`. `/refactor` refuses at runtime on an unresolved name, but that fires only in a consuming repo, never in the plugin's own CI. Fully deterministic and exhaustive — the cheapest complete test available.
- **Sync-set agreement.** Contracts with must-stay-in-sync copies (the always-on default set across setup + `docs/reviewers.md`; the close-out-pair description across the two READMEs, `DIFF-MATERIALIZATION.md`, `STORE.md`, and `CONTEXT.md`; the parse-coupled agent output-section headings quoted in both the agent body and the calling skill) have no check that the copies agree. Ticket 005 shipped four such drifts that survived to the refactor pass.
- **Register placement.** From spec 006 ticket 003's refactor pass (qa-engineer): the register-ahead-of-halt rule (EVIDENCE-PRINCIPLE.md) is mechanically greppable — no agent body's `## Output format` may contain a halt/stop instruction after `### Partial verdict`. Covers all fifteen bodies plus every future one; same deterministic-and-exhaustive shape as the manifest-resolution check.

- **Bare `[[ ]]` / `(( ))` in a `.bats` body.** From spec 006 ticket 006's refactor pass (qa-engineer + software-architect, converged). Both forms are exempt from `errexit` on bash 3.2 — fired and confirmed: a non-final `[[ 1 == 2 ]]` and `(( 0 ))` each leave their test green, while `[ 1 = 2 ]` and a failing `grep -q` each fail it. Ticket 006 converted all 54 occurrences and the tree is clean today, but the invariant is *standing* and its only enforcement is prose in two documents. The gate that would catch a regression is `bats plugins/pirr/scripts/` — and a newly added inert assertion is invisible to it **by construction**, since its whole defect is passing. That makes this the sharpest member of this set: unlike the others, the existing verification cannot fail on it even in principle. One grep over `plugins/pirr/scripts/*.bats`, failing with the offending file and line, and the rationale carried in the failure message rather than in the two prose copies.

The repo already mechanized its one deterministic artifact (`materialize-diff.sh` + a bats suite) on exactly this "a script cannot skip a preflight" rationale — this is the same move for the prose contracts. Adjacent to the banked `serialize-preflight-script` idea (both mechanize prose invariants) and `canonical-edit-conformance-sweep` (ADR-0002 hot-path copies specifically); worth grilling together to decide one harness or several. Open question at promotion: how to declare a sync-set machine-readably (a manifest of copy locations? anchored comments?) so the check knows what must match without re-encoding every contract by hand.
