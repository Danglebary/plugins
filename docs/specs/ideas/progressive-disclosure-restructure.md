# Restructure the skill corpus by progressive disclosure

From a deep review of the `work-plugins` fork, whose spec 006 (`progressive-disclosure-restructure`, ADR 0034) restructured its entire skill corpus around one claim about the harness: a skill's full `SKILL.md` body loads at invocation and persists for the session, invoking a second skill *adds* its body rather than swapping it, and supporting files in a skill directory load **only when explicitly read**. So conditional prose is not free — a session ingests every branch it never takes, for its whole life. The fork's answer: a lean `SKILL.md` becomes a **Router** carrying only the branch-neutral spine, and each branch's prose lives in a **Variant** file read at the moment its axis resolves.

The convention is four rules and a gate template. **The Split test**: one topic, one small home; a closed taxonomy (routes, phases, verdicts, modes) gets a file per member; citations point at the smallest home that answers the question; applied recursively to `_shared/` as much as to skills; keyed on *topic shape, never word count*. **The treatment rule**, by fork shape: a large contiguous fork → Variant files; a small repeated clause → a tightened citation to its shared home; a deep-dive or rarely-entered arm → a read-on-demand companion gated by the question that makes it relevant; a fine-grained sentence-interleaved fork → *drain* it first (extract the shared contracts it re-renders, leave the genuinely-local residue inline), then split whatever residue is still fork-shaped. **The citation anchor rule**: cross-file citations address contracts by *name*, never by step number — a named contract survives renumbering, a step number rots silently. **The gate template**, a step rather than an offer: *"When `<axis>` resolves to `<branch>`, read `<file>` now — it is the branch taken. The other `<axis>` variants are not read."* Plus one structural invariant that turns out to do most of the reshaping work: **no file outside a skill's own `SKILL.md` may link to one of its Variant files**, which forces every both-branch surface into the spine, a shared leaf, or a question-gated companion.

The honest payoff analysis matters more than the convention, because the fork measured it and the result is mixed. Its corpus **grew 11% at rest** (32 files / 64.6k words → 81 files / 72.0k words) while any single session's read path fell to **47–64%** on the heavy skills — and on its lightest split skill the less-common path came out *worse* than before the split. The lesson it states directly: per-path read cost is dominated by the always-read spine plus shared rules, not by the unread branches, so per-path targets need spec-time arithmetic rather than aspiration. Its big wins came from one 7.5k-word monolith with 64% conditional mass on a genuinely closed axis (`Visibility`, public↔private) — a route axis this repo does not have and, being files-store-only (ADR 0003) and single-user (ADR 0001), will never grow.

That argues for cutting this in two halves that are independently promotable. **Half one pays regardless of route axes**: the convention doc itself, the Split test applied to `_shared/`, and the citation-anchor discipline. The candidates are already visible — `STORE.md` is cited by all 26 non-`_shared` markdown consumers in the plugin, the exact "multi-topic body every reader must excavate" shape the fork's own `STORE.md` failed the Split test on at severity 1; `RECOVERY.md` (12.5 KB, the largest `_shared` doc) already ships an informal lazy-load contract and is *missing from the `_shared/README.md` index* entirely; and the two skills already split use contradictory naming (`refactor/` uppercase, `tdd/` lowercase) that a stated convention would settle. **Half two is the Router pass**, and it should be justified axis by axis rather than applied uniformly: `/setup`'s first-run vs re-run arms, `/to-spec`'s three-way fit check, `/next-ticket`'s tdd-vs-implement mode recommendation, and `/done`'s outcome-label and refactor-or-merge forks are real closed taxonomies, but the three heaviest procedural skills (`/refactor` 17.6 KB, `/done` 15.6 KB, `/retro` 15.1 KB — all monolithic, all loading `STORE.md` + `DIFF-MATERIALIZATION.md` + `CLOSE-OUT.md` + `ABSTRACTION-LEVELS-PRINCIPLE.md` on top of their own bodies) are heavy from *sequential procedure*, which the pattern does not compress at all.

Three mechanical supports came out of the fork's run and are worth stealing whole, because they are what converted the work from judgment into checklist. A **census** frozen before any edit — per-file word counts, per-skill axes with their conditional weight and interleaving shape, per-`_shared`-doc Split-test verdicts with severity — declared to go stale as waves land, because that is its function. An **anchor map** cataloguing every cross-file citation, annotated in place per ticket as each is dissolved; its citation graph is what bounds safe write parallelism (never rewrite both endpoints of a citation concurrently). And an executable guard suite: a `lychee --offline --include-fragments` link check (fully generic, ~20 lines, catches dangling headings the way nothing else does), plus router-shape and anchor-audit checks whose *structure* ports even though every table row is this repo's own content. The guard suite grew mid-spec and caught live defects each time it grew; enrollment in it is stated as part of authoring, not an afterthought.

Two failure modes to design against, both discovered the hard way. **Cite-plus-copy** — prose that gains the canonical citation but keeps its own enumeration anyway — is invisible to a lossless audit (nothing lost, something retained) and recurred across four consecutive waves before a uniqueness guard pinned it. And **decomposition creates new adjacency**: clauses that were harmlessly imprecise inside a monolith become live contradictions once a citation drags a shared home's text into the same executor context as the local prose. The fork caught several of these only via fresh-context adversarial verifiers deliberately run on a *different model* than the writers.

Open questions at promotion: whether to promote half one alone and let half two wait for evidence that route-conditional mass is actually accumulating; whether a CI hook is wanted or authoring-time `check.sh` invocation suffices (the fork shipped no CI); and how this composes with the banked `manifest-and-syncset-ci-guard`, `canonical-edit-conformance-sweep`, and `serialize-preflight-script` ideas, which all propose mechanizing prose invariants and are probably one harness rather than four. The fork also banked a successor it considered seriously and deferred — replacing model-navigated file-tree disclosure with a deterministic CLI over an encoded variant store, rejected for now because the filesystem already computes the same function (path = input tuple, file = output, `Read` = query engine) with zero added toolchain and a compiled artifact is one git can't diff and a reviewer can't read. Not worth carrying here until hop latency across a much larger skill set is an observed problem.
