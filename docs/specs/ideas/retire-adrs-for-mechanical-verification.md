# Retire ADRs from the workflow, and push what they carried into enforcement

ADRs are a human-optimized artifact that misfires under an agent-first paradigm, and this workflow should stop shipping them. Three failure modes compound. **Silent staleness**: an ADR's Context section is prose making present-tense claims about how the system is, and code moves while the paragraph does not — a stale claim still enters an agent's context and is reported as current fact, with nothing anywhere that fails. **Artificial narrowing**: reduced re-litigation is not a side effect of the ADR, it is the product; humans discount old documents and smell staleness, agents defer to formal in-repo text far more readily, so the same artifact suppresses first-principles reasoning much harder for the reader it now mostly has. **Authority laundering**: when a human writes an ADR the writing is itself a costly signal that someone cared enough to formalize; when an agent writes one that signal is gone but its appearance survives, so the next agent infers deliberate human intent behind a document that may have come from a passing remark — unearned authority, in the format engineered to discourage re-examination.

The minting decay is observable rather than theoretical. Agents increasingly emit ADRs for implementation and design details that are neither architectural nor foundational, and the three-gate test does not stop it because the gate is prose too — interpreted, never enforced. A recent session is a clean sample: an agent extracting decisions from a legacy design-doc archive proposed seven ADRs, three did not survive review, one rested on a premise the code contradicted (a security property the repo documented but did not implement), and one shipped with a sentence that was **born stale** — it asserted a present-tense architectural fact that the same session had, twenty minutes earlier, banked a plan to change. Roughly a fifty percent defect rate, from an agent applying the three-gate test deliberately with a human reviewing. In the same session every mechanically verified claim — toolchain probes, a preflight test, the pre-commit gate — held without exception.

Nothing is lost that this workflow does not already home better. Spec-local decisions live in a spec's **Approach**, boundary decisions surfaced during grilling live in **Non-goals**, and the retro assesses per section how well those decisions actually held — so the considered-and-rejected alternatives already have a place, and it is one the reader can date. The structural argument is the sharp one: **an ADR is the only artifact in this store that claims to be currently true indefinitely.** A spec freezes at `Open` and is a snapshot of intent at a moment; a ticket is a bounded unit of work; a retro is explicitly backward-looking. All three are past-tense by construction. Removing ADRs removes the single artifact whose shape guarantees the rot, and leaves no hole behind.

Prior art converges on the same split from three independent directions. Dan North, asked what holds what an executable spec cannot — *"what we dismissed… I don't know we also considered Y and Z but went with X because unicorns"* — routes it deliberately away from the checked artifact and into dated, timestamped entries. Cyrille Martraire names the form an **Account from the Past**: *"As a story anchored in the past, it's always an accurate story."* The AWS ShardStore team reached the same place and reversed an earlier choice to get there, moving their reference models out of Alloy and SPIN and into Rust in-tree, explicitly for long-term maintenance. The durable home for un-checkable knowledge is not *more structured*, it is **dated and past-tense** — which a spec already is. The adoption record says the same thing from the market side: `adr-tools` has ~5,600 stars and verifies nothing, ArchUnit has ~3,800 and succeeded precisely by dropping the decision framing to become dependency rules as tests, and every explicit attempt to bridge the two sits in single-digit stars.

What replaces the enforcement half is a lint, an assertion, or a test whose **failure message carries the deliberateness bit**. That bit is what an ADR was mostly buying: an accepted ADR in a consuming repo spent six kilobytes of prose to convey *this is intentional, do not normalize it back* — the one thing a future contributor, human or agent, actually needed. Delivered as a check's failure message it arrives at the moment of violation, to the agent about to make the mistake, cannot be skimmed past, and cannot go stale, because if the rule stops holding the check stops passing. `cargo-deny`'s `reason` field is the shipped precedent: of the architecture-rule tools surveyed it is the only one with a first-class slot for rationale attached to a machine-checked constraint, and it works not because the rationale is verified but because it is co-located with something that is, and therefore gets read exactly when it matters.

The removal is substantially larger than deleting a format doc, and the size is itself the most interesting evidence. **ADRs are cited 182 times across 45 files of the plugin corpus** — `ADR 0005` 48 times, `0006` 43, `0008` 26, `0004` 23 — and the heaviest skill surfaces are `/refactor` (13 mentions), `/done` (11), `/grill-me` (10), `/retro` (6), with all fifteen reviewer agents referencing ADRs and twelve `_shared` documents doing the same. But reading what those citations *do*, almost none of them defer to a decision: they invoke **doctrine that governs skill behavior** — how reviewers treat diff-touched authority, how coverage claims split by attestability, how planted-instruction reporting converges. That is principle, not decision, and this repo already has the right container for it in `_shared/EVIDENCE-PRINCIPLE.md`, `CONTENT-CHANNEL-PRINCIPLE.md`, and `ABSTRACTION-LEVELS-PRINCIPLE.md`. **The fact that this plugin's most-cited ADRs are principle documents in the wrong container is evidence the form was being misused by its own author**, which is the same drift observed in consuming repos, one level up.

So the shape of the work: delete `ADR-FORMAT.md`; drop `docs/adr/` from what `/setup` provisions and from `STORE.md`'s artifact map; remove `/grill-me`'s three-gate test and its inline minting, and `/refactor`'s mint-on-rejection path; migrate the load-bearing doctrine now living in ADRs into `_shared` principle documents, leaving the historical *why* in the spec that produced each one; sweep the fifteen agents and twelve shared docs; and settle what `ABSTRACTION-LEVELS-PRINCIPLE.md` becomes, since its middle tier — seam-level, owned by deviations and ADRs — loses half its membership. In exchange, `/setup` should lean harder on what does survive: stricter lint and test scaffolding, with the reviewer fleet already covering the standards half. Two cautions the research is emphatic about and the sweep should encode. The **escape-hatch ratchet** is universal — every ecosystem that added expressiveness to a verification mechanism got directive proliferation, ArchUnit ships `FreezingArchRule` specifically so teams can record thousands of known violations and keep the build green, and every `#[allow]` is an unverified claim wearing verified clothing. And the dominant failure of checked artifacts is the **silent downgrade**, not the missing check: a Go example without `// Output:` is compiled and never run, a Rust `no_run` block is never executed, a `+SKIP` once hid a numerically wrong example for years — so the strength of a claim must be machine-visible, not merely the claim, and CI should assert a test *count* rather than only a green result.

Open questions at promotion: whether this repo deletes its own `docs/adr/` or keeps the eight as frozen history while the product stops shipping the artifact — `ADR 0004`'s consent-vs-ceremony test is live doctrine cited 23 times and needs a `_shared` home either way; whether the 182 citations migrate one-for-one into principle docs or the sweep consolidates them, since several ADRs likely collapse into a single principle; whether `/grill-me` loses the three-gate test outright or it becomes a narrower prompt asking whether a decision warrants a check; whether `ABSTRACTION-LEVELS-PRINCIPLE.md` keeps three levels with seam-level rehomed onto deviations alone or collapses to behavioral and code-shape; whether `/setup` gains lint and test scaffolding in the same pass or a later one; and what consuming repos with populated `docs/adr/` are told — the README already carries migration notes for the PRD-era rename and the `agentic-flow` rename, so a third note is the established shape, and the honest default is that existing ADRs stay put as frozen history and no new ones are minted.
