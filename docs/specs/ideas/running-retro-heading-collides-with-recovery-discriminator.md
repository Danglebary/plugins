# The running retro's title heading is the shape RECOVERY.md calls a corrupt rewrite

From ticket 001's refactor pass (technical-editor), verified against git history. `RECOVERY.md`'s closed-spec recovery arm keys a **destructive** route on a shape: *"A rewrite that crashed mid-write leaves a hybrid instead — a `# Retro:` heading with leftover per-ticket entries, or visibly truncated sections. A hybrid is a corrupt rewrite, not a landed one: restore the committed running form (`git checkout -- <retro path>`) and re-synthesize."* But `# Retro:` heading plus per-ticket entries is exactly what a **running** retro looks like in this repo. `docs/specs/005-rename-to-pirr/retro.md` at its creating commit `518f4ef` is `# Retro: Rename to pirr` followed by `## Ticket 001 — …`; spec 006's is the same shape. So the discriminator cannot separate a legitimately-dirty running retro from a half-written synthesis, and the arm it may route to runs `git checkout --` over uncommitted work.

The mismatch is a format-doc-versus-practice split, not a bug in either file alone. `RETRO-FORMAT.md`'s "Running form" specifies per-ticket entries only, and `/done` step 8's template is `## Ticket NNN — <title>` with no title heading — yet `/done` also says "creating the file if it doesn't exist", and every dogfooded run has created it with a `# Retro:` line. Five specs' retros carry it. So the practice is uniform and the format doc simply never described it. **Pre-existing, not introduced by ticket 001** — that ticket merely made a sixth instance and put a reviewer's eyes on it.

Two coherent resolutions, and they pull opposite ways. Either the running form officially gains the title heading — `RETRO-FORMAT.md` and `/done` step 8 both say so — and `RECOVERY.md`'s hybrid test re-keys on something that actually distinguishes the two states (per-section outcome labels co-resident with `## Ticket NNN` entries, or visible truncation alone); or the running form stays heading-free, `/done` step 8 states that explicitly, and the five existing retros are left as legacy. The first is less churn and matches what the workflow actually does; the second keeps `RECOVERY.md`'s discriminator as written. Worth a ticket sooner than the other banked ideas: it is the only one whose failure mode destroys prose the user wrote, and the arm that would do it is already shipped.
