# The store's artifact map misses plugin-local glossaries

Hit during spec 006's `/to-tickets` run (2026-07-19). `STORE.md`'s artifact map defines the Glossary as **`CONTEXT.md` at repo root**, and three consumers glob the store-artifact paths from that map: `/to-tickets`' serialize-ticketing precondition 3 (*clean* means no tracked modifications outside those paths), its bootstrap edit set, and `CLOSE-OUT.md:7`'s gated-commit enumeration. This repo also carries `plugins/pirr/CONTEXT.md` — the plugin's own domain vocabulary, where **Reviewer agent**, **Workflow agent**, and the close-out pair are defined, and where spec 006's grill minted four new terms. That path is in none of the globs.

The result is a two-sided failure that only appears when pirr is run against the pirr repo. Precondition 3 classifies a grill-minted Glossary edit as *implementation dirt* and refuses the bootstrap — the opposite of the precondition's own stated carve-out, which exists so *"grill-minted Glossary/ADR edits are legitimate planning dirt the bootstrap will commit."* And had it not refused, the bootstrap's authorship-scoped edit set would have *excluded and named* the same file, cutting the spec branch without the vocabulary its tickets are written in, leaving those terms uncommitted on the default branch. Spec 006 proceeded by naming the file as a deliberate exception in its bootstrap commit rather than by changing the map under time pressure.

The fix is a design call, not a glob edit, because the underlying question is whether a plugin-local `CONTEXT.md` is a **store artifact** or **product content**. It is genuinely both here: it ships to consumers as part of the plugin, *and* it is the artifact `/grill-me` updates inline when this repo dogfoods its own workflow. Candidate shapes: extend the map to `**/CONTEXT.md` (simple, but sweeps any consuming repo's vendored copies); name the plugin glossary explicitly as a second Glossary row (honest, but concedes there are two Glossaries and owes a rule for which one a term belongs in); or declare plugin-local glossaries product content and require them to be committed separately (consistent with treating `plugins/**` as implementation, at the cost of splitting one grill's output across two commits). The middle option probably wins, but it needs the term-placement rule written with it.

Worth noting the general shape, since it is the same one spec 006 is about: a path-based rule that merges two unlike things, discovered only when a case outside its authors' mental model showed up. Adjacent to the banked `manifest-and-syncset-ci-guard` idea — a machine-checkable store map would have caught this as a resolution failure rather than as a mid-bootstrap refusal.
